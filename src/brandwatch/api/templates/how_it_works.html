STEP 3 / 6 · VISIT{% if not F %}illustration{% endif %}

It visits every site the way a victim would.

Many phishing kits hide from security scanners: a harmless page for datacenter IPs, the fake login only for real people. So BrandWatch also visits as a real person.

  • A real Chrome: its User-Agent, Accept-Language, client hints, language and time zone all agree — no "HeadlessChrome" giveaway.
  • A real address: through a residential or a mobile 4G / 5G proxy (or both) in the brand's country, as a desktop and / or a phone.
  • A locked-down browser that can't reach internal systems; everything it sees is kept as evidence nobody can edit.

The score uses what a victim sees, not what the kit chose to show a scanner.

STEP 5 / 6 · DECIDE & MAP{% if G.illustrative %}illustration{% endif %}

Nothing is confirmed automatically: an analyst reads the evidence and presses Confirm. From that one site, BrandWatch follows what the attacker reused — server, certificate, favicon, tracking code, owner — to the rest of the operation.

  • Neighbours that only share a cheap server are dropped as noise, with the reason written down.

One fake site leads to the whole operation, and every indicator exports to a SIEM as STIX 2.1.

Guided tour · 8 stops· a ten-minute walk through the app, with the questions people ask
  1. Dashboard — the mission line and the five-step strip

    “BrandWatch finds sites impersonating a brand — on the web and in Facebook / Instagram ads — proves it with tamper-proof evidence, maps the attacker's servers and drafts the takedown. A human decides every step.”

    Likely question: what's real here? → In demo mode every external service is a recorded scenario; the same code calls VirusTotal, crt.sh, Google and Chromium in live mode.

  2. {% if stops.brand %}The brand page{% else %}A brand page{% endif %} — tick “include fingerprinting”, press START SCAN

    “First it learns what the real site looks like, then it hunts for copies on five streams.”

    Likely question: how do you find domains that don't exist in any list yet? → Permutations checked in DNS, new certificates in CT logs, yesterday's registrations.

    Likely question: what about ChatGPT and Gemini? → With AI answers on, the approved questions (support phone, contact, login, fraud) are asked to ChatGPT, Gemini and Google AI Mode; every contact in the answers is compared with the ones on the brand's own website, a mismatch gets a "show me the official page" follow-up, and BrandWatch opens the cited pages itself before it raises a finding.

    Likely question: what about social media? → Facebook pages by name (Meta's page search, every country) and Instagram / Facebook profiles Google knows; each one's page history, logo, links and posts are checked and an AI reads the content. Fakes become findings with a Report-to-Meta box, a link in their bio goes to the website checks, and the brand's own accounts are never flagged. Ads about the brand are searched too, per country.

  3. The live scan console — then “▶ replay highlights”

    “Every step is narrated as it happens; the report at the bottom says what the scan did in plain words.”

    Likely question: what if VirusTotal is down? → Retries with backoff, a circuit breaker, then the next provider in the chain; the alert panel says what happened and how to fix it.

  4. {% if stops.cloaked %}A cloaked kit{% else %}A critical finding{% endif %} — read the two-sentence summary, then the three screenshots

    “This kit shows a blank page to scanners and the login page to real visitors. We fetch it like a victim would.”

    Likely question: why is VirusTotal at 0? → It's days old; blocklists lag. Unknown is never treated as clean.

  5. Explain Finding — signals, group caps, the score line, “open the arithmetic”

    “Deterministic, explainable scoring: every point traces back to evidence. Risk and confidence are separate axes. The AI is advisory.”

    Likely question: false positives? → Penalties (old domain, redirects to the brand), a whitelist, and a golden-dataset regression gate (precision / recall ≥ 0.90).

  6. Press Confirm phishing, then Investigate site & network

    “Confirming maps the attacker's infrastructure automatically. The investigation tabs on the finding page replace twenty minutes of VirusTotal, urlscan and RDAP tabs.”

  7. {% if stops.campaign %}The attack infrastructure map{% else %}Attack infrastructure{% endif %} — drag the graph, read two triage reasons

    “One site led to the whole operation. Noise is triaged out with a reason; the indicators go to a SIEM as STIX.”

  8. {% if stops.takedown %}The takedown{% else %}Takedowns{% endif %} → Activity

    “Three channels — registrar, host, CDN — plus the blocklists. Every step is in an append-only audit log the database won't let anyone edit.”

Under the hood· the engineering an interviewer asks about

SSRF guard & sandbox

Every fetch: validate the URL → resolve A/AAAA → fail closed on {{ facts.limits.blocked_networks }} blocked networks (private, loopback, cloud metadata) → connect pinned to the validated IP with Host + SNI → re-validate every redirect hop (≤ {{ facts.limits.max_redirects }}) → size ≤ {{ facts.limits.max_response_mb }} MB, timeout {{ facts.limits.fetch_timeout_s }} s.

The same policy gates every Chromium sub-request. Limits are frozen in code — no brand, workspace or env var can change them.

security/fetcher_guard.py · security/limits.py · see it in Settings

Immutable evidence

{{ facts.immutable_tables|length }} append-only tables: database triggers reject UPDATE and DELETE — even for an admin, on SQLite and PostgreSQL. Artifacts are content-addressed: the SHA-256 is the file name.

Each finding links its evidence with a role (primary, supporting, contradicting, context): a chain of custody for a takedown or a court.

db/models · migrations/001 · evidence/store.py{% if stops.cloaked %} · see it on a finding{% endif %}

Provider resilience

Every external call goes through one wrapper: TTL cache → budget check → circuit breaker → token bucket → retry with backoff (honouring Retry-After) → the next provider in the fallback chain.

A bad key disables the provider for the job instead of failing 500 calls; "unknown" is never treated as clean.

providers/base.py · providers/registry.py{% if stops.scan %} · see the alerts panel{% endif %}

Cost ledger & budgets

Every paid call is recorded with its cost; daily call and spend caps are checked over the trailing 24 h before the call, so a scan stops spending instead of overspending.

providers/ledger.py · budget meter

Durable live events

Each scan writes an ordered event stream (sequence-numbered, secrets redacted) before publishing it over SSE; a refresh resumes from the last event. Cancellation is cooperative at safe checkpoints.

Secrets, tenants & roles

API keys are envelope-encrypted (random 32-byte key per record, AES-256-GCM, bound to workspace:provider). Passwords: Argon2id. Personal API tokens are stored as SHA-256 only; a read-scoped token caps even an admin at viewer.

Every query is workspace-scoped; RBAC (admin / analyst / viewer) is identical in the UI and the API.

Trust & safety

  • A human decides every verdict and every takedown; nothing is ever sent automatically.
  • Residential IPs are used to look like a victim, never to interact; probes never submit forms.
  • The AI only gives advisory opinions under a strict JSON schema, with the page text framed as untrusted.
  • Only brands you are authorised to protect; every action is in the append-only audit log.
