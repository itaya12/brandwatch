Provider API keys · AES-256-GCM envelope encryption, never shown again

The services BrandWatch calls during a scan. Demo mode answers every call from recorded scenarios, so no key is needed here. A missing key never breaks a scan: that source is skipped and the console says so. Each key gets its own random 32-byte data key (AES-256-GCM), wrapped by the master key and bound to workspace:provider; only the last four characters are ever displayed.

Residential / mobile proxy

Optional. Used only by the Tier-4 cloaking probe: re-fetching a suspicious site from a real home or phone-network IP, as a desktop browser and/or as a phone, to catch kits that hide from datacentre scanners or that only target mobile victims. The country is chosen per brand, from its audience. Never used to interact with a site.

A phone visit is also made from the data-centre IP (free) when "mobile" or "both" is chosen, because kits that target phones show the lure to a mobile browser whatever the address. Through the proxy it costs the same as a desktop visit, once per device and per proxy. Every visit except the crawler's is a real Chrome: its User-Agent, Accept-Language, client hints (sec-ch-ua), language and time zone agree with each other and with the proxy's country.

Fixed security limits · not configurable by brand, workspace or environment

What happens before BrandWatch fetches anything from a suspect site — the same policy for the HTTP client, every Chromium sub-request and the TLS probe.

  1. Validate the URL: http/https only, allowed ports, no credentials, no internal host names.
  2. Resolve A / AAAA and fail closed if any address is private, loopback, link-local or cloud metadata — 24 blocked networks; IPv4-mapped IPv6 is unwrapped first.
  3. Connect pinned to the validated IP with the original Host header and TLS SNI (defeats DNS rebinding).
  4. Re-validate every redirect hop · at most 5 redirects.
  5. Response ≤ 5.0 MB · timeout 15.0 s.
  6. Infrastructure pivots stop at depth 2, 100 nodes, 300 edges.
